# Service depth trials

The **Serwis** tab tests cutting depth without changing the uploaded file or
writing a new work zero. The operator starts every scan and cut explicitly.

## Operator flow

1. Set material Z zero, then place the tool at the desired local XY origin,
   between work Z=0 and Z=3 mm. Verify the probe contact and open it again.
2. In **Frez V**, set tip diameter (0.01–0.5 mm) and full included angle
   (10–90 degrees), initially 0.1 mm / 30 degrees. Set nominal strip width
   (0.2–2 mm). Width can change between trials or after mapping. Set XY feed
   (10–300 mm/min), Z plunge feed (1–100 mm/min), and spindle S (1–1000).
   These speeds can change between trials, including after mapping; never during
   an active scan or cut. Adjust depth from 0.01 to 0.30 mm using the
   number, slider or 0.01 mm buttons. Editing never sends motion.
3. Confirm **Zmierz 5 punktów**. The tool first moves to work Z=1 mm, then
   probes the four corners and centre of a 12 x 5 mm rectangle at F20, down
   to work Z=-0.4 mm. Existing X/Y/Z work offsets remain unchanged.
   Each probe descent is limited to 1.4 mm total travel, not Z=-1.4 mm.
   File-bound grid scans enforce the same cap, including their first reference
   touch. Default grid clearance is 1 mm and search below zero is 0.4 mm.
4. Read the five measured heights and range. Remove the clip from the tool,
   clear the wire, check the checkbox and confirm **Wykonaj próbkę**.
5. Inspect the 10 mm groove and the nominal 10 mm copper strip enclosed by
   a narrow isolation contour. Adjust the next trial and measure the next field.
   Its origin is +6.5 mm in Y from the previous field. Even a stopped trial
   consumes its field; it cannot be cut again with the old map.
6. Save a completed trial as the working profile. Tool parameter changes require
   a new Z map; width and speed changes do not. Start a new session to choose
   a new XY origin. Probe feed remains F20 and G0 uses controller speeds.

The preview shows the expected pattern, not a measured or simulated cutting
width. The live theoretical groove width is `tip + 2 * depth * tan(angle/2)`.
XY offsets use the selected tool and the currently requested depth. Opposite
contour centrelines are separated by `strip width + groove width`; subtracting
the theoretical groove width leaves the requested strip. The longitudinal
contour also accounts for the tool radius to preserve nominal 10 mm length.
The browser preview and backend both recalculate these offsets when depth changes.
Actual strip width can differ due to runout, tool errors or mechanics.
S is controller scale, not measured RPM.
The 12 mm field includes margin around the 10 mm specimen. Combinations whose
predicted tool sweep does not fit the field are rejected before probing/cutting.

## Map and execution

Five-point interpolation uses four triangles sharing the measured centre.
Heights are relative to the existing work Z zero. Feed moves are subdivided
by the existing surface compensation code; rapid moves retain global clearance.
No G10 work-zero command is generated by the service scanner.

The service uses the existing exclusive serial owner, probe heartbeat, job
heartbeat and Stop handling. It keeps its job separate from the uploaded
production file. During service motion, other manual/program actions are blocked.
Changed work offsets, missing contact, alarm, timeout or lost connection prevent
reuse of the map. Stop retains the application's existing reset/disconnect
behaviour; it does not promise a controlled retract or spindle stop.

Profiles are stored atomically in the service user's
`~/.local/share/bark-beetle/milling-profile.json`. Only completed trials can be
saved. A profile stores tip diameter, full angle, depth, nominal strip width,
XY/Z feeds and S, not a calibrated
effective tool diameter. Check the result again after remounting/replacing a tool.

In **Plik**, the optional profile-depth checkbox replaces the negative cutting
depth in an execution copy only. It rejects multiple negative depth levels,
combined XYZ moves/ramps and rapid plunges. XY, positive clearance moves and
the original upload are preserved. Apply the file's surface map separately;
the small service map must never compensate an unrelated PCB file. CAM offsets
are not regenerated by applying depth.

## Manual movement and calculation audit

In **Ruch**, choose 0.1, 1, 10 mm or **Własny**. Enter a positive custom step
using a decimal point or comma. Editing never moves a machine; each direction
button applies one step. Blank, nonfinite and invalid steps disable motion.
Per-command limits are X=300, Y=180 and Z=10 mm; the UI receives them from the
backend. These are software bounds, not detected remaining machine travel.

The default profile applies no extra calibration. The top bar reports
**Korekta: brak**. Named measured profiles expose every fitted coefficient
in the top bar; they never change machine steps or manual jog distances.
Completed-trial history records the actual requested parameters plus theoretical
groove width and contour centreline spacing used for that execution. Physical
width remains unverified without measurement of the groove/tool/mechanics.

## Measured calibration profiles

In **Profile → Profile kalibracji**, enter a name, tool tip, full included angle,
XY feed, plunge feed and spindle S. One manual measurement is sufficient;
additional observations are optional (up to 8). Enter cut depth, nominal strip
width (the value set when cutting that sample), and actual remaining strip
width. For iterative calibration the actual width can be 1 mm
after adjusting the nominal strip until the measured strip is 1 mm. No recorded
trial or automatic output is required. Creation stays enabled with empty or
invalid values; clicking it reports what needs correction. Only an outstanding
request temporarily disables the submit button. Saving requires Idle or a
disconnected CNC and never selects the new profile automatically.

Each row exposes the diameter used to generate the sample's tool path. It
initially follows the nominal V-tool formula. If that sample used another
diameter, such as one from a calibrated CAM profile, enter that value explicitly.
**Rowek z geometrii frezu** restores the nominal calculation for that row.
The optional history section still accepts recorded completed trials only.

The backend derives `D_actual = D_used + nominal_strip - measured_strip`.
`D_used` is the explicitly supplied CAM diameter for manual measurements or
the actual recorded diameter for history entries, including previous calibration.
With one observation, the slope remains `b = 2*tan(angle/2)` and the measured
diameter determines `a = D_actual - b*h`. The visible constant correction is
`offset = a - tip`. The profile uses this same offset at other depths within
the service limit of 0.01–0.3 mm; these are predictions, not measured depths.
Nonpositive predicted diameters are rejected. RMS error is not defined for
one observation. Both the offset and reference depth appear in the top bar.

For multiple observations, least squares fits `D(h) = a + b*h`. This is a
tool-width model, not axis steps calibration, backlash correction or a
guarantee of physical accuracy. Non-increasing fits are rejected. The fit
is usable only between its smallest and largest measured depth. Those samples
must use different depths (at least 0.01 mm apart). RMS residual
is shown; with two observations it is zero by construction.

Creation reports success or a specific validation failure beside the form.
Profile mutations force a fresh status read even if an older poll is in flight,
so the top-bar options reflect the saved state. If that refresh fails, the form
distinguishes a saved profile from an unavailable list; it does not claim that
the save failed. Creation does not activate a profile. Select it in the top bar,
where `a`, `b` and fixed cutting depth remain visible. Selection persists across
restarts and requires Idle or a disconnected CNC. It invalidates file/test maps
but leaves the independent service map valid. Serwis never applies the active
profile. The **Profile** tab contains the fixed-parameter nine-point test; see
[Fixed-depth profiles and isolation tests](profile-tests.md). Jog, zero and
probing distances are never scaled by profiles.

Profiles, selection and up to 100 completed observations are stored atomically
in `~/.local/share/bark-beetle/calibration-profiles.json`. Up to 30 named profiles
are supported; edits change the fingerprint and retain internal snapshots.
Export profiles before deleting them. A damaged
store is preserved and blocks calibrated operations rather than silently
applying a different model. The old **Zapisz parametry** preset is separate;
it does not create a geometry calibration profile.

### PC CAM workflow

Export JSON from the profile's details, then on the PC run:

```powershell
python scripts/calibration_cam.py profile.json
```

Use the printed `tool_diameter_mm` as the CAM effective milling diameter,
`cut_z_mm` as cut depth, and the displayed feed, plunge and power conditions.
Generate the isolation paths again in the existing PC CAM workflow. The helper
does not run CAM or adjust XY in an existing NC. After generating the final
linear GRBL file with those parameters, explicitly declare its provenance:

```powershell
python scripts/calibration_cam.py profile.json --tag final.nc --output final-profile.nc --confirm-cam-profile
```

The helper checks file limits, depth, feeds and power, then adds an ASCII
profile ID and fingerprint comment. It preserves every original command and
refuses to overwrite a file. The marker is an operator declaration that CAM
used the exported tool diameter; it cannot verify XY geometry from a finished
NC. Upload `final-profile.nc`. Start requires the matching selected profile
and unmodified CAM feeds/depth. Calibrated files with XYZ ramps are rejected.
Existing untagged NC files require Default. Surface compensation is applied
after this check and retains profile metadata. CAM remains on the PC.
